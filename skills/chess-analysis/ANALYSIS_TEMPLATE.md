# 棋局复盘文件模板（review.md）

> 本模板指导**每一盘将要分析的棋局**如何输出复盘文档。
> 数据一律来自 `data/{date}_{game_id}/` 下三个 JSON，**不要手写/臆测数值**：
> - `metadata.json` — 对局元数据（双方、结果、日期、时控、开局）
> - `pgn.json` — 着法序列 + 每步 FEN
> - `engine_eval.json` — Stockfish 评估（`evaluations` / `blunders` / `mistakes` / `missed_wins`）

---

## ⛳ 评估口径（铁律，违反即全盘皆错）

1. **评估一律白方视角**：`eval` 正 = 白方优，负 = 黑方优，**与轮到谁走无关**。
   （历史 bug 用了走子方视角，导致符号逐步翻转、白方完胜被误判成步步昏招。）
2. **丢分（`eval_drop`）按走子方计算**：白方走子丢分 = 评估下降；黑方走子丢分 = 评估上升。
   对决定性优势已**钳制**（±10 兵封顶），所以「完胜局里的小波动」不会被算成昏着。
3. **昏着排序按 `eval_drop` 倒序**（丢分越大越靠前），**不是按步数**。
4. **`missed_wins`（错失速杀）不是昏着**：原本可将杀、走完仍完胜，单独叙事，绝不混入昏着榜
   （否则会出现「丢 992 分」这种被将杀哨兵值放大的误导标题）。
5. **着法记号用 `san` 字段原样**（如 `Ba6`，不是 `Bxa6+`）。
6. **始终点名棋手**：提到「白方/黑方」必带具体用户名（如「白方 aaronwang2026」）。

## 正文结构

### 标题
```
# [白方] vs [黑方] | [日期] | 执[白/黑][胜/负/和]
```

### 总体评价
一段话概括：结果 + 关键转折点 + 一句最重要的教训。教练口吻，先肯定再点问题。

### 🎯 亮点时刻
- 1-3 个值得肯定的着法（从 `evaluations` 找评估上扬或顶住压力的关键手）
- 每条：步数 + 着法 + 一句话点评

---

### ⚠️ 关键失误（按 `eval_drop` 倒序，取 TOP 3-5）

> 数据源：`engine_eval.json.blunders` + `mistakes`，按 `eval_drop` 从大到小。

1. **第 X 步 [san]** — 💥 BLUNDER（丢 **X.XX 兵**）
   - 评估：白方视角 +A.AA → +B.BB
   - 应走：`[best_move]`（[best_score]）
   - 原因：……（这步让对手……/错失了……）

2. **第 X 步 [san]** — 💥 BLUNDER（丢 **X.XX 兵**）
   - ……

> 📖 **失误等级**
> - 💥 BLUNDER（昏着）：`eval_drop` > 1.0 兵
> - ⚠️ MISTAKE（一般失误）：0.3 ~ 1.0 兵
> - Inaccuracy（小失误）：0.1 ~ 0.3 兵

---

### 🕒 错失速杀（如有 `missed_wins`，单独列）

> 这些**不是昏着**：原本能更快将杀，但走完仍稳稳完胜。

- **第 X 步 [san]**：本可 `[best_move]`（[best_score]，如 Mate +3）速杀；
  实走后仍 +X.X 完胜，只是错过更快的结束。

---

### 💡 可以更好的地方
- 3-5 条具体改进建议（连接失误，给可操作的方向）

### 📚 开局学习建议
- 2-3 条针对本局开局（`opening`）的学习点

### 🌟 今日收获
- 3 条一句话总结

## 附录

### 局面评估走势（白方视角）

[执白/执黑]（[目标棋手用户名]）共 **X 次昏着 + Y 次失误**（另 Z 次错失速杀）

> 💥 = BLUNDER（>1.0兵） ⚠️ = MISTAKE（0.3-1.0兵） 🕒 = 错失速杀
> 评估列为**白方视角**：正=白优，负=黑优。

| 步 | 着法 | 评估(白方视角) | 丢分(走子方) | 标记 |
|----|------|---------------|-------------|------|
| 1.白 | e4 | +0.45 | — | |
| 1.黑 | e5 | +0.39 | 0.06 | |
| 2.白 | Nc3 | +0.14 | 0.25 | |
| …  | … | … | … | |

**说明：**
- **评估列**：直接取 `engine_eval.json.evaluations[*].eval`（已是白方视角）。
- **丢分列**：取 `eval_drop`（仅失误/昏着步有意义；正常步可留空或填小值）。
- 不要再像旧模板那样把白方着法写成负分——那是已修复的符号翻转 bug。

---

### 关键局面 FEN（失误前局面，便于导入棋软复盘）

> FEN 取「失误着法**之前**」的局面 = `pgn.json` 中上一手之后的 `fen`
> （ply 索引 `(move_no-1)*2 + (0白/1黑)` 的前一项），这样箭头才标得对。

| 步 | 失误着法 | 应走 | FEN（失误前） |
|----|---------|------|--------------|
| 第 X 步 | [san] | [best_move] | `...` |

## 备注

- **正文关键失误**：只选 TOP 3-5，每条含 步数 + 着法 + 等级 + 丢分 + 应走 + 原因。
- **附录走势表**：可列全部步，量化整体表现。
- **FEN**：短棋（<30步）可省；长棋（>50步）记 3-5 个关键局面。
- **一切数值以 `engine_eval.json` 为准**，模板里出现的具体数字仅为格式示例。
